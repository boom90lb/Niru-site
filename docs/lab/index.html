Inside AMLO

How a study is designed to run, what it records, and what exists today. The procedure is the design AMLO is being built around.

The diagrams model the design. The claim record is simulated. Neither demonstrates an end-to-end AMLO search or a gain at target scale.

Why it matters

Small-scale evidence can mislead expensive decisions. A design that wins among small models can lose at full size. A candidate that trained a little longer, or drew a better learning rate, looks like a better architecture. The best of a hundred noisy scores is biased upward, because the noise helped to choose it. A careful researcher catches some of these. That care is hard to reproduce, hard to audit and does not scale with the number of experiments.

A procedure that collects the evidence against a result before it spends more compute gives fewer expensive false leads, a clear reason for each allocation of compute, and results that a partner can examine instead of take on trust.

The first application

The first kind of study answers a question that comes before every large run. Of these model architectures, which one should we train? Candidates are compared at small scale under one fixed training recipe and matched compute. A design moves to a larger scale only when the evidence at the smaller scale supports it, and it replaces the current best only when it is still better at the larger scale.

How a study runs

AMLO is being built around this procedure. Every candidate goes through the same sequence.

  1. Declare. Before any run, the study states what changes, what stays fixed and which resources count.
  2. Check. Each proposal passes a graph check, port checks, scaling checks and a static compute estimate. A proposal that fails is rejected before it trains.
  3. Match compute. Within one comparison, each candidate and the current best get the same compute target. A larger model trains for fewer steps, and each run records a receipt of the compute it used.
  4. Compare in pairs. Candidates train from one seed and are scored on the same examples. Their losses are compared example by example, so much of the shared noise cancels.
  5. Promote on evidence. A candidate advances only when the interval for its improvement is above the current best, and an exact bound on the bootstrap’s error shows the required confidence is met. A Benjamini–Hochberg filter then limits the share of false promotions in each batch.

Promotion has three tiers. Each tier asks one question, with more compute; the later tiers ask for stricter confidence than the first.

Tier 1
Is it better at the proxy size?It trains with the same compute as the current best. 95% confidence.
Tier 2
Is it reproducibly better?A new seed, new examples and five times the compute. 99.9% confidence.
Tier 3
Is it still better at twice the width?Both designs train wider, with settings moved by u-μP’s rules, under one compute target. 99.9% confidence.

Only a candidate that passes Tier 3 replaces the current best. Deterministic checks decide what is legal, and a statistical policy decides which candidate gets compute. In a later stage, an agent can propose changes, but it cannot decide what passes.

What the search edits

In AMLO’s next design, the whole training step is one typed expression, a term, that holds the model, its loss, the gradient derived from them and the update. The search changes a model by editing its term, and the cost of each edit is counted exactly from the definitions before anything trains. The drawing on the home page shows two models written this way.

An exact representation can make a declared operation count exact. Hardware time and physical device work are separate measurements. It does not by itself show that a small model predicts a large one. That is a separate question, which Tier 3 asks of every winner and which the spectral study examines in a toy model.

How a result is read

Each result is an improvement in held-out loss, Δ = reference loss minus candidate loss, with an interval around it. Positive means the candidate has lower loss. Where the interval falls against the reference gives one of three outcomes.

  • Supported. The whole interval is above the reference, at the confidence fixed before the run.
  • Inconclusive. The interval crosses the reference. The record keeps the result and its reason. It is not a loss.
  • Refuted. The whole interval is below the reference.

The final comparison uses a fixed reference, the current best when the search began, so gains are never chained from one best to the next. Before it runs, the selection and the analysis are frozen. An Auditor, apart from the search, holds a sealed set of examples that the search never saw and opens it only after the freeze.

What a study records

A study ends with a claim record, whatever the outcome. The record below comes from a simulated run. The site models AMLO’s proposed search rules, and the losses come from a synthetic model. The site’s replay checks do not qualify AMLO’s implementation.

In 500 seeds of the same simulator, the final comparison is supported in 300, inconclusive in 89 and refuted in 111. A design that wins the search is not certain to win at full size. The record says which happened.

Where it stands

AMLO is a research prototype. Its single-device reference trainer and mathematical foundation exist. The search path that enforces matched compute still stops before its first training step, and the restricted paths that do train do not yet produce an admitted search result. The next milestone is one completed, reproducible search comparison with declared compute accounting, followed by independent confirmation.

The central claim, that a search run this way picks designs that hold at full size for less compute than the usual process, is not yet shown. The tests below are how it will be shown, or refuted.

The next tests, in order

  1. Trained candidates. Can one candidate comparison complete under a declared compute-accounting method, with exact recovery from a checkpoint?
  2. One credible comparison. Does one search run end to end, from a frozen selection to a sealed confirmation?
  3. Proxy validity. Do results at small scale predict results at the target scale?
  4. Policy value. Does a search policy find better designs than a fixed baseline, for the same compute? This is a separate study.
The full ledger, reviewed 10 October 2026, with training and accounting refreshed 14 October
  • Reference trainerBuilt

    The reference trainer, written with JAX, Flax and Optax, trains one configured model from start to finish on one device.

  • Checks before trainingBuilt

    Every proposal passes a graph check, port checks, declared u-μP scaling checks and a static FLOP estimate before it can train. A proposal that fails is rejected at the cost of the check.

  • Term algebraBuilt

    AMLO implements the term layer of Abbott and Zardini’s algebra of deep learning. It covers categories with copies and deletes, axes and their index maps, arrays and weaves, an operator library, and exact and real semantics, with exact forward and backward work for a program. The search does not run on it yet.

  • Candidate training in the searchPartial

    The search path that enforces matched compute asks for a seal before the first update and stops there, because the direct measurement of each training step’s compute is not built yet. Restricted training paths without the seal exist, but they do not produce an admitted end-to-end search result.

  • Compute planningPartial

    A deterministic planner converts a tier’s compute target into a step count. The current accounting method counts the complete training step as the compiler models it. Declarations and seals exist, but they do not yet permit a run or qualify a result. Modeled work is not physical device work or wall-clock time.

  • Paired statistical promotionPartial

    A BCa bootstrap interval on paired per-example loss differences decides promotion, and its resampling seed is a hash of the evidence. A Benjamini–Hochberg filter runs over each generation’s provisional promotions; the design applies it to every candidate tested. Where pairing evidence is missing, the code falls back to an unpaired interval.

  • Uncertainty-aware screeningPartial

    Quantile models over structural and spectral graph features rank first-tier candidates by a lower confidence bound on predicted loss. The ranking decides who trains, never who is promoted. The models fit only on trained candidates, so they have not run yet, and sampled audits of screened-out candidates are not built.

  • u-μP parameter scalingPartial

    In a model that declares its scaling, the optimizer applies a u-μP factor to every parameter and refuses a parameter without one. This is a precondition for transfer; transfer itself is not tested yet.

  • Random streams and checkpointsPartial

    Proposals come from a counter-based Threefry generator. Each checkpoint saves the random state with the population, and a run resumes from the last committed checkpoint. Exact recovery is not yet proven.

  • Decision recordPartial

    Every proposal and every rejection goes into an append-only event log, and an analytics index can be rebuilt from it. A claim bundle and a verifier for it are not built.

  • Frozen selection and sealed confirmationPartial

    A one-way sequence of phases freezes the selected design before a sealed confirmation set can be used. The Auditor role and its independence receipt are not built.

  • Distributed trainingNot built

    Training on many devices and many nodes. Placement and sharding will be recorded choices about where a run happens.

  • Training-program searchNot built

    Search over data mixtures, schedules, objectives and optimizers, with the program that trains a model as a candidate in its own right.

  • Deployed-system searchNot built

    Search over the model together with its tools, memory, retrieval, verifiers and inference budget, so that the comparison is the system a user meets.

  • Whole-training-term integration and term searchNot built

    The 0.0.14 design puts the whole training step in one representation, with shape-parameterized definitions, a derived backward pass and typed search edits. The term algebra exists, but joining this whole training path to the search is still design work. The drawing on the home page illustrates those definitions.

Where it goes

Architecture is the first object of the search, not the last. The design widens it in three stages, with the same rules for comparison and evidence at each.

  1. Architecture and implementation. Candidate architectures change in small steps under one compute budget.
  2. Training program and curriculum. The program that trains the model joins the search, with its data mixtures and their schedules, filters, objectives, optimizers and the phases of training.
  3. Deployed model–harness system. The deployed system joins the search, meaning the model with its tools, memory, retrieval, verifiers and the inference resources it can spend.

The long-term aim goes one step further, to a system that applies the same procedure to its own method, and keeps a change to how it searches only when a sealed comparison supports it. That is a research aim, not a stage of the current plan. It needs its own evidence that each change to the method helps.
